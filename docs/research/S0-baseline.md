## 已发现风险与处理边界

1. 原 pytest fixture 使用业务配置并清表：本轮新增强制测试配置、仅本机 attendance_test_* 库名防护；未建库、未清表。专用账号权限隔离仍待配置。
2. 关闭识别线程只等待三秒即清引用：长推理退出风险待专项复现，本轮不改业务线程。
3. get_name.py 写固定 face.jpg 并逐图比对：后续内存适配、模板缓存和加密迁移的共同前置项。
4. 现有 UI 独立测试使用假识别和假服务，不证明真实模型、主线程回传及数据库端到端正确。
5. 活体开关不是安全降级：要求活体时，失败或无法判断不得自动绕过。

## 安全测试入口

- 无数据库验证：直接运行 tests/test_database_safety.py 和 tests/test_anime_ui.py，不通过 pytest 启动。
- 后续数据库测试必须显式设置 ATTENDANCE_TEST_CONFIG，指向单独的本地 INI；禁止 attendance_config.ini。
- 测试配置结构与 ConfigService 一致，数据库必须为 attendance_test_ 加小写字母、数字、下划线。
- 不自动生成凭证，不复制正式配置。建议测试专用 MySQL 账号仅有专用库权限。
- 通过检查后 pytest 仍会删除测试库中的记录，库名防护不能替代专用账号和独立数据。
- 尚未执行数据库测试；需先确认隔离配置与账号，获准安装缺少的测试依赖后再做。
