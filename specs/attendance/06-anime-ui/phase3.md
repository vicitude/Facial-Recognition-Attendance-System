# 第三阶段：识别体验与主线程隔离

## 范围
- 将实时签到中的 YOLO/FaceNet 推理从 Qt 主线程移到单个短生命周期 QThread。
- 保留现有摄像头预览、水平翻转、识别阈值、员工关联、打卡确认和未识别停止规则。
- 不修改 recognition.py、get_name.py、数据库、Service API、原始 ui.py。

## 不变量
- 摄像头预览由主线程持续更新；推理最多同时存在一个任务。
- 推理 worker 只返回检测/特征阶段的 name；EmployeeService 查询、QMessageBox、CheckConfirmDialog 全部在主线程执行。
- 新帧在识别忙时丢弃，不排队、不使用旧帧覆盖当前预览。
- 停止识别后，已提交任务允许完成但其结果不得弹出确认框或恢复识别状态。
- 关闭相机/窗口停止定时器、释放摄像头，并等待正在运行的推理线程结束。

## 可观察 UI
- 识别开始后状态显示“识别中...”或“正在分析画面...”。
- 推理异常显示既有错误提示；未知结果沿用既有警告和自动停止行为。
- 识别成功后仅由主线程更新结果卡并弹打卡确认框。

## 验证
- 独立 Qt unittest 模拟 worker，不加载真实模型和数据库。
- 覆盖：忙时不重复提交、成功回主线程、停止后丢弃结果、推理异常回主线程、关闭释放线程。
- 100%/200% 缩放测试继续执行；本阶段不运行会清理业务表的 pytest。
