# 三次眨眼融合活体：现场验证

## 当前 v1.4.0 操作（覆盖下方历史三随机动作说明）
先完成睁眼→闭眼→重新睁眼校准，校准不计眨眼次数。随后按提示完成三次独立眨眼：每次睁眼建立基准，再闭眼、重新睁眼保持稳定；每次之后等待身份复核，再做下一次。无需转头或点头。长闭眼不累计多次，三次后仍等待被动辅助检查；R清空全部状态重新开始。
本阶段验收仅真人、完整纸质照片、手机静态照片，各20轮、至少两种光照/距离，真人>=18/20、攻击各0/20为研究候选；移动/弯折纸照和移动屏幕也需测试。手机视频、挖眼照片不在本阶段防护承诺中，可另行记录。未现场验收，不接正式签到。

以下四类/随机动作内容保留为历史记录，不是当前默认操作。

状态：待现场执行。自动化轨迹通过不代表真人或攻击验收通过。

## 启动
在项目根目录打开 PowerShell，使用项目已安装依赖的 Python；摄像头编号可调整。关闭其他占用摄像头的软件。

```powershell
$env:PYTHONUTF8='1'
python fused_liveness_research.py --camera 0 --category live
```

类别：live=真人；paper=纸质照片；phone_photo=手机静态照片；phone_video=手机视频。

1. 准备阶段按中文指令依次自然睁眼保持片刻、正视闭眼保持片刻、重新睁眼保持片刻；这是本轮眼部校准，不计入三个随机动作。20秒内未完成会显示校准超时，按R重试。校准后正视睁眼等待三份身份基准，再进入随机动作。无需强行瞪大眼达到固定0.28。
2. 按当前指令完成一个动作，再回正并睁眼保持稳定，等待三份新的正视身份复核通过后才开始下一动作。动作中距离超过0.8只作诊断，不能据此判失败或放行。最后还需七份身份合格的live辅助确认。
3. 摄像头画面直接显示中文动作、建立基准/回正提示、完成进度及失败原因；Pillow使用Windows中文字体绘制，不依赖OpenCV内置英文字体。预览镜像不改变推理帧。修改后必须退出旧进程重新启动。
4. 左右指人体自己的左右；第一次实测必须确认方向一致，如相反不能按通过验收，应报告符号问题。
5. passed/failed/timeout后画面停止分析，按R随机新一轮；Esc退出。不要中途按R抹去失败，完整记录每次重试。
6. passed只代表本次研究组合条件成立，不写考勤记录，不表示生产安全。

## 原因解读
- passive_spoof：被动模型判疑似攻击；即使是真人也不可绕过，需收集现场结果后标定。
- passive_not_confirmed：三个动作结束但末尾7帧被动模型未全部确认。
- need_one_face/poor_quality：脸数量或质量不合格。
- identity_changed：身份数值无效，或回正后连续三份正视采样距离超过0.8；固定身份基准由准备阶段三份稳定采样建立，不随当前人脸更新。动作期间有限非负超限距离不再单次拒绝。仍需真人及中途换人实测。
- identity_check_timeout：动作回正后5秒内未获得三份稳定正视且距离<=0.8的身份结果；保持正视睁眼，记录数值后按R重试。
- trajectory_jump/frame_gap：运动突变或处理帧间隔超过0.5秒；后者可能是CPU推理太慢，不应当作攻击被拦的有效证据。
- action_timeout/session_timeout：超过单动作10秒或总计35秒。

## 四类样本
每类至少20轮，至少两种光照/距离组合；每轮新挑战。
- 真人：本人执行指令，含眼镜场景。
- 纸照：高清打印、平移/旋转/弯曲纸张尝试。
- 手机照片：不同亮度、移动/旋转屏幕尝试。
- 手机视频：有眨眼/左右转头/点头的视频，允许攻击者尝试匹配随机顺序。
